已修复其他场景只有字幕而没有触发旁白的问题。N01–N17 全部绑定到对应事件；38 段固定台词通过本机 SenseAudio 服务成功生成、缓存。角色仍共用账号已有的“播音”音色，并保留角色参数配置。

## 衔接规则

- 原童谣先播放；自然结束后接 N01，已进入餐厅则再接 N02。稍后才推门时，单独播放餐厅环境旁白。广播重听结束接 N04，不重复开场介绍。
- 先显示字幕、准备反馈，约 320ms 后播放语音并用 20ms 渐入。歌曲约 1 秒渐入；主动打断时约 140ms 渐出，新声等前声停止后起声。
- 背景音乐探索时 32%，语音前降至 8%；两句之间保留低音量，结束后先留白 450ms，再用 700ms 恢复。童谣、麦克风和集中推理发言期间暂停背景音乐。
- 切换物件、发起新问题、打开弹窗、返回和重置取消旧台词及后续片段。加载超过 18 秒取消，不会之后突然补播。
- 记录判断立即保存；收尾旁白在结果弹窗内播放，字幕、状态和停止入口同时出现。关闭结果弹窗便取消旁白。

## 检查范围

34 项 JavaScript 测试、11 项 Python 测试和 TypeScript/Vite 构建通过。音频测试覆盖渐入渐出、串行播放、加载超时、自动播放重试、麦克风即时静音、取消、销毁、背景开关与全局静音偏好。浏览器实测的是播放状态、字幕与交互流程；本轮未采集真人麦克风语音，未对不同设备的扬声器响度作主观听感校准。当前依然是单人演示和预设对话。

## 起声与账户状态更新

旁白已改为自然语速 1.0、音高 0；人声只保留 20ms 防爆音渐入，字幕提前量保留。新的渲染版本参数会绕过浏览器旧音频缓存。35 段当前参数台词生成成功，其余 3 段基础质询目前可使用相同文字和音色的既有缓存（旧语速音高）。

平台随后明确返回 base_resp.status_code=400、status_msg=计费账户已被冻结。原因未知，不推断为余额不足。已有缓存继续使用；没有对应缓存的新配音暂时无法生成。服务端仅在冻结时复用相同模型、相同文字、相同 voice_id 的既有配音，不把回退音频写成新的参数缓存。
