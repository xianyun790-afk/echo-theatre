# 0.2.3 语音交互验收

日期：2026-10-28。检查范围：第二幕主持人的语音转文字、连续追问、插话、时间线导航、异常退出和手机操作。

## 修复

- 复现打开活动时间线导致主持人组件卸载、麦克风和连接关闭的问题。现在时间线在主持人面板内展开，连续会话继续保留；普通档案入口仍可独立查看时间线。
- 将时间线内容提取为共享组件，仍仅展示已公开陈述，不把私人草稿或未公开观察交给主持人。
- 增加“你的原话”，保留最终识别或输入的文字，避免回复开始后看不到识别结果。
- 主持人面板使用独立阅读滚动区，麦克风、文字输入与发送按钮保持可见。桌面、手机及较矮窗口均可操作。
- 主持人提示调整为简短直接回答，只在玩家明确要求导航时调用工具；强调撞击声不能直接证明死亡时间、名册字迹书写时间未知，避免补写未经公开的剧情。

## 真实服务测试

使用 macOS Tingting 合成语音，经桌面 Chrome 的测试麦克风采集路径上传，连接实际 NIA ASR、模型与流式音频服务；不是模拟识别结果。

三句均完整识别，显示中间识别文字；同一会话完成连续追问与回复中插话。时间线展开后主持人仍挂载，麦克风继续工作。收到1,040,000字节PCM，音频包间隔中位数50ms、P95为57ms、最大92ms。关闭后采集轨道ended、两个AudioContext均closed，无页面脚本错误。

上述时间从整句识别完成起算，不包含说话、等待停顿、浏览器缓冲和扬声器实际发声时间；单次本机测试，不是延迟保证。测试未覆盖真人硬件麦克风、口音、嘈杂房间或主观音色满意度。

本地备用模式另测真实Vosk HTTP识别，仅将NIA可用状态设为不可用：同一句“停电后的撞击能证明死亡时间吗”识别成功，服务返回200，识别请求处理约0.77秒，页面显示本地预设回应；关闭释放采集资源。

## 交互和异常检查

- 模拟传输配合浏览器真实测试麦克风：连接中取消、权限拒绝、网络断开均停止采集并清理资源；错误时可使用备用入口。
- 关闭按钮、Esc、点击遮罩三种退出方式均释放轨道和AudioContext；重新打开可发送文字，私人草稿不发送。
- 时间线与连续问答复用一个会话，未提交的角色活动保持隐藏，原话持续显示。
- 1366×768、390×844、667×500：麦克风和发送按钮无需滚动即可操作，无横向溢出。
- Node测试74项通过，类型检查与生产构建通过。构建仍有现有大包体积提示。
