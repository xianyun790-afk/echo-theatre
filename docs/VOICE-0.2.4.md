# 0.2.4 语音与文字切换修复

日期：2026-10-28。基线：0.2.3。适用第一、二幕共用主持人输入组件。

## 已复现并修复

1. 中文输入法选字时按Enter会提前发送。实时与本地两种模式均检查组合输入状态和浏览器isComposing / keyCode 229，完成选字后再按Enter才发送。
2. 只发文字时，麦克风按钮也显示“结束语音对话”，点击只能关闭会话。按钮现在按实际麦克风模式显示；文字问答期间可以直接开启麦克风，复用原连接。未开麦时的回复状态不再提示可直接说话打断。
3. 主持人服务状态返回后，输入组件由本地切换到实时，导致已输入的草稿丢失。草稿现在由公共父组件保存，服务选择及备用模式切换时保留。
4. 检查服务期间不启动本地采集或发送问题，避免随后模式切换打断刚开始的操作。输入框仍可打字；服务检查最多等待5秒，超时后开放本地备用模式，草稿不丢失。

## 验证

浏览器修改前复现：草稿消失、输入法回车误发、文字提问后不能直接开启麦克风。修改后同组检查全部通过，无页面脚本错误。

- 390×844手机画幅：服务检查完成后草稿保留，实时模式组合输入期间不会发送，结束组合输入后正常发送。先文字提问再点麦克风，浏览器实际采集并发送PCM成功。
- 实际NIA服务：先用文字问调查方向，再开麦输入合成语音“停电后的撞击能证明死亡时间吗？”，整句识别一致，原话保留并收到回复。只创建一个会话，发送771个麦克风包，累计收到401600字节回复PCM。关闭后track为ended，两个AudioContext为closed，无页面脚本错误。本次未使用放宽自动播放限制的浏览器启动参数。
- 服务状态请求不返回：5秒后进入本地模式，输入草稿保留；准备期间不会发送或开启麦克风。本地模式组合输入期间不会发送，选字完成后正常发送。
- Node测试74项、TypeScript检查和生产构建通过。

本次使用合成语音经浏览器测试麦克风上传到真实服务，未声称覆盖真人设备、口音、环境噪声或主观音色验收。0.2.3的三轮识别、插话和时间线连续会话验证记录继续保留。
