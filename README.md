# 第七个孩子 · 第一、二幕本地试玩

本地可交互三维试玩，未发布。基于原创《第七个孩子》的第一、二幕，风格调整为哥特暗黑童话：手绘材质、旧物、冷灰蓝与暖黄灯光。无人物立绘，主要焦点是旧广播与物证。Three.js实时渲染房间、门、广播、桌椅、手印；场景不是背景图片。

## 仓库交接与部署

本仓库当前为 **0.2.8，包含第一、二幕**，第三幕尚未开放。Git 历史保留最初的第一幕版本。

- 部署步骤与验收：[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)；Nginx 示例：[config/nginx.example.conf](config/nginx.example.conf)。
- 完整部署资源：[v0.2.8 Release](https://github.com/xianyun790-afk/echo-theatre/releases/tag/v0.2.8) 的 ZIP 附件，包含中文识别模型、82条配音和 manifest。克隆源码后，也需从该包复制 `echo-theatre/.local-asr/` 到工程根目录；保留隐藏文件。
- 密钥由部署者在服务器 `.env.local` 配置，示例见 [.env.example](.env.example)。远程麦克风需要 HTTPS，还需按部署说明设置正式 Origin 并运行两个后端服务。
- 仓库为私有；部署者须获仓库访问权限，或由项目所有者转交完整部署 ZIP。

## 启动

```sh
cd echo-theatre
npm ci
npm run dev -- --port 4177 --strictPort
```

打开 http://127.0.0.1:4177/ 。直接打开源码 index.html 会自动跳转到此地址（需本地服务正在运行）。

`dev` 同时启动网页、本地配音/中文识别服务（127.0.0.1:4178）与 NIA relay（127.0.0.1:4179）。本机已安装识别运行环境与模型。换电脑时先运行 `python3 scripts/setup_local_asr.py`，再启动网页；模型缓存在忽略目录 `.local-asr/`，不进入网页构建产物。

## 第一幕体验

1. 门前先展示故事前情：林见秋的身份、火灾记忆与匿名邀请。推门后打开角色本，阅读当前目标与私人记忆，点击「我已了解，开始调查」后播放《小朋友》（约26秒）。阅读期间不播放开场音频、不开启主持人和搜证；刷新可恢复未读完的角色本。老存档直接继续调查，前情和角色本均可回看。
2. 点击广播可以停止或走近重听；播放时开关和指示灯变化。按下鼠标拖动广播可以轻微转动查看。声音线索以原始录音为准，不再使用旧版“六只碗、七把匙”的推断。磁带是待比对资料，不声称已经发现音轨差异。
3. 点击窗、木柜查看环境反馈，点击“检查餐桌下面”，摄像机蹲到桌下。
4. 点击手印或“记录这条线索”，将物证放入证据本；可返回餐厅继续调查。
5. 常驻提问栏可直接点麦克风对话，或输入文字按 Enter 发送，无须先展开面板。配置 NIA 后，浏览器通过 getUserMedia 与 AudioWorklet 采集声音，以16kHz PCM 小包流式上传，边说边显示识别结果；停顿窗口为600ms，整句识别后由实时模型回应，可打断。未配置或手动切换本地试玩时，使用本机 Vosk 与预设回应。也可以询问许知音的磁带，以明确标注的预设资料演示另一位玩家贡献线索。
6. 收齐三条线索后“召集大家，集中推理”，镜头回到同一张桌前。六个角色依次陈述，玩家输入自己的发言并引用证据，其余五人为明确标注的预设发言。
7. 指定对象质询，至少提问一次，再选择本轮优先核查的疑点。保存记录后结束第一幕，不进入后续幕或指认凶手。更多选项另有演示跳转，预置三条公开线索。

右下方“线索”“我的剧本”“更多”为辅助入口，连同试玩说明、记录与第一幕回顾统一使用居中弹窗，长内容在弹窗内滚动。当前迭代优先适配桌面网页。

## 实际能力与限制

- 当前单人、本地浏览器进度，无多人房间服务。其他玩家贡献由预设台词模拟。
- 固定配音使用 NIA 的7套独立音色，共58条播放路径，已预生成并保存在本机；旁白与实时主持人共用晚舟。音色清单见 config/nia-voices.json，试听页 /voice-audition.html。
- 配置 NIA 后主持人接入 SenseNova 实时模型，限制在第一幕已公开事实内；集中推理的角色发言仍是预设脚本，无真人多人服务。
- 早期的系统声音 WAV 仍保留在 public/audio 作历史占位素材；当前主持人与角色播放入口已经切换到本地 /api/tts 接口。广播使用用户提供的原始 MP3，保存为 public/audio/opening-song.mp3，原文件未修改。
- 背景音乐使用用户提供的《背景音乐.mp3》（项目内 public/audio/background-music.mp3），循环播放，常态音量 32%；开场童谣或广播歌曲播放时暂停背景音乐，歌曲结束后再从原位置恢复；主持人或角色说话时降至 4%，结束后恢复。开启语音对话前先将背景音乐静音，再中断当前语音、开启麦克风；识别和主持人回应期间持续静音，结束对话、识别报错或退出时恢复，避免背景音乐被录入或在打断广播时突然变大。已移除原先合成的雨声；更多选项中的“背景音乐”可单独关闭，顶部静音同时控制音乐与语音。
- 未配置 NIA 时，语音输入使用 [Vosk](https://alphacephei.com/vosk/) 与官方 [中文小模型](https://alphacephei.com/vosk/models)，通过同源 `/api/transcribe` 发送到回环地址的本机服务。音频不上传第三方、不保存到磁盘，识别文本交给本地预设主持人逻辑。识别器不是公司模型，人名或复杂句子可能识别不准；可随时切换文字。浏览器只需支持麦克风和 AudioWorklet，不再调用不稳定的浏览器云识别服务。
- 用户指定的 MiniMax 音色样本保存在 public/audio/narrator-reference.mp3，仅作为统一旁白与主持人音色参考，尚未用它生成其他台词。当前已用 NIA 音色库生成固定台词，未克隆参考样本。
- 角色本是固定视角的体验内容，不提供生产级私人信息隔离。联机版需服务端按角色、阶段和公开状态控制信息。
- 核心业务模块：src/lib/act-one.ts；音频生命周期：src/lib/audio.ts；未来公司接口契约提案：src/lib/voice-adapter.ts。后者不是公司真实API。

## 检查

`npm test` 检查第一幕回复、集中推理条件、记录恢复、音频生命周期与 PCM 重采样；`python3 -m unittest discover -s tests -p '*_test.py'` 检查识别接口的音频格式校验；`npm run build` 执行类型检查和生产构建。

雨窗使用独立程序化材质（src/lib/rain-window.ts）：远景树影、月光、玻璃水珠、流动水痕及折射。减少动态效果设置下停止水痕和视角跟随。

## 资产

前期美术草稿使用内置ImageGen，保留在 public/images/dining-gothic.jpg 与 public/images/stool-gothic.jpg 。最新版本改为程序化三维房间（src/components/Room.tsx），前期图片保留作美术参考，不作为主场景背景。生成提示见 docs/ASSETS.md 。当前三维造型仍是本地交互原型，不等于最终精修美术。

此前注册的Sites标识保留在 .openai/hosting.json，当前工作不会同步源代码或部署。

开场在页面载入时自动尝试播放用户的童谣原音，无播放器界面。如浏览器禁止自动有声播放，首次点击或按键自动重试；推门时继续当前音轨，不叠播、不从头播放。墙上广播可重播同一首歌。重新体验也会重启开场童谣。

音频切换统一由 SceneAudio 管理：同页面同时只保留一条前景音轨和一条背景音轨，童谣与背景音乐不同时发声。替换前景音轨时先停止旧音轨，移除监听与对应隐藏元素。旧的独立 useOpeningMusic 播放入口已移除。

## 旧 SenseAudio 服务端配置（历史保留）

密钥保存在已忽略的 .env.local（权限600），变量名 SENSEAUDIO_API_KEY，不使用 VITE_ 前缀。服务优先读取本项目配置，然后才回退到同名环境变量。角色与固定台词在 config/voices.json；后端 scripts/senseaudio_tts.py 仅合成白名单台词，不接受前端任意文本或任意上游地址。音频缓存到已忽略的 .local-asr/senseaudio/cache，相同台词重听不重复请求云端。

前端使用同源 /api/tts/<clip-id>；模型合成的是固定脚本配音，不代表已接入自由剧情生成。新整理的 N01–N17 已加入可合成目录，仍需逐个绑定场景节点；本次已替换当前正在使用的主持人和集中推理配音入口。

弹窗新旧纸边缘使用本地 SVG 蒙版和纸张颗粒；标题使用本地子集化 Ma Shan Zheng（public/fonts/archive-display.woff2），官方 OFL 许可保留在 public/fonts/MaShanZheng-OFL.txt。

## 当前 NIA 配音

AK/SK 仅存在本机 `.env.local`。固定台词 `node scripts/nia-render.mjs` 预生成到 `.local-asr/nia/cache`；播放服务只读取已核对正文与音色 ID 的缓存，不重复请求云端。实时主持人通过本机 relay 连接 NIA，麦克风音频经同源 WebSocket 中转发送至 NIA；纯文字提问不采集麦克风。完整协议、角色对应与验证见 docs/NIA-INTEGRATION.md。
